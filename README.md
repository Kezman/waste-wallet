# Кошелёк, подожди — прототип

Кликабельный прототип сервиса против импульсивных покупок: заявка на расход, голосование
незнакомцев с обязательным аргументом и пауза вместо мгновенной оплаты.

**Без бэкенда и базы данных.** Все данные живут в браузере (localStorage), ответы API
имитируются задержкой. Внешний вид и сценарии — настоящие, серверная часть — заглушка.

## Запуск

```bash
npm install
npm run dev      # http://localhost:5174
npm run build    # типы + production-сборка в dist/ (~360 КБ)
```

## Куда выложить бесплатно

Это статика: `dist` можно отдать любым CDN. Конфиги для основных вариантов уже в проекте.

| Хостинг | Бесплатно | Плюсы | Что учесть |
| --- | --- | --- | --- |
| **Cloudflare Pages** | без лимита трафика | быстрый, свой домен бесплатно, `_redirects` уже лежит | нужен аккаунт Cloudflare |
| **Netlify** | 100 ГБ/мес | выкладка перетаскиванием папки без git | иногда медленнее из РФ |
| **Vercel** | 100 ГБ/мес | деплой из git в один клик | `vercel.json` с rewrite уже есть |
| **GitHub Pages** | 100 ГБ/мес, 1 ГБ репозиторий | бесплатно и навсегда, git-история | нет SPA-fallback: воркфлоу копирует `index.html` в `404.html` |

Самое быстрое — **Netlify Drop**: `npm run build`, открыть `app.netlify.com/drop`, перетащить папку `dist`.
Самое надёжное для демонстрации и Telegram Mini App — **Cloudflare Pages**: подключить репозиторий,
build command `npm run build`, output directory `dist`.

Для GitHub Pages в проекте есть `.github/workflows/deploy-pages.yml`: он сам собирает с префиксом
`/<repo>/` и публикует. Нужно только включить Pages → Source: GitHub Actions.


## Что можно потрогать

| Экран | Адрес | Что проверить |
| --- | --- | --- |
| Очередь заявок | `/` | фильтры, поиск, счётчики «не потрачено» |
| Заявка | `/request/req-6` | голосование с обязательным аргументом |
| Закрытая заявка | `/request/req-9` | вердикт «Отклонено», итог «купил / удержался» |
| Новая заявка | `/new` | валидация полей, живой предпросмотр карточки |
| Мои заявки | `/my` | личная статистика |

**Демо-панель** — `/ ?dev=1` (круглая кнопка с ползунками справа внизу):

- сдвиг времени на +6 / +24 / +72 / −24 часа — чтобы увидеть истечение срока без ожидания;
- «имитировать сбой сети» — проверка ошибок в формах;
- гостевой режим — что видит человек без права голоса;
- сброс демо к исходным 24 заявкам.

Переключатель темы — иконка солнца/луны в шапке. Выбор хранится в `localStorage`, по умолчанию
берётся системная тема.

## Что именно имитируется

`src/lib/store.ts` — единственное место, где живут данные и «задержки сети». Когда появится
сервер, меняются тела методов `createRequest`, `castVote`, `setOutcome` на `fetch`, а экраны
и типы остаются прежними. Контракты (`src/lib/types.ts`) уже описывают будущие сущности:
заявка, голос, решение, исход.

Имитация честная в двух местах: задержка 300–500 мс и опциональная ошибка сети, чтобы UI
проектировался под состояния загрузки и сбоя, а не только под счастливый путь.

## Структура

```
src/
  lib/            типы, seed-данные, store, тема, форматирование, хук времени
  components/     шапка, карточка, статус-бейдж, счётчик голосов, форма голоса, иконки, дев-панель
  pages/          лента, заявка, создание, мои заявки
  styles.css      дизайн-система на Tailwind 4: токены света/тьмы и примитивы
scripts/          служебные CDP-скрипты для скриншотов и проверки вёрстки
docs/screenshots/ снимки экранов
```

## Дизайн

Современный «продуктовый» интерфейс: нейтральный фон и белые карточки с мягкой тенью и
скруглением 18 px, градиентный акцент индиго→фиолетовый на главных действиях, пилюли-фильтры,
tabular-цифры для сумм, статус-бейджи вместо печатей. Есть тёмная тема: все цвета заданы
CSS-переменными на `:root` и `[data-theme="dark"]`, поэтому переключатель меняет всю палитру
без перерисовки классов.

Ирония «бюджетного отдела» осталась в текстах (заявление, заключение, карма согласующего),
но ушла из визуального слоя — интерфейс должен выглядеть как продукт, которому доверяют
деньги, а не как шутка.

## Ограничения прототипа

- нет бэкенда: данные не синхронизируются между устройствами и живут до очистки браузера;
- «сообщество» — это seed-данные, реальных людей нет;
- нет модерации, антиспама, авторизации;
- срок закрытия заявки считается на клиенте по сдвигу времени, а не по серверному планировщику.
